# 자주 묻는 질문

## PR이 닫혔어요. 어떻게 하나요?

봇의 댓글을 확인하세요. 어떤 항목을 통과하지 못했는지, 여러분의 출력이 어땠는지, 그리고 오류 메시지가 적혀 있어요. 고친 뒤 **새 PR을 열면** 돼요(같은 브랜치를 그대로 써도 돼요).

PR을 열기 전에 로컬에서 `pnpm judge <내 GitHub ID>`로 먼저 테스트해 보길 추천해요. 채점 환경은 온라인과 똑같아요.

## 병합된 뒤에도 작품을 수정할 수 있나요?

네. 접수 기간 중에 자기 폴더를 수정하는 PR을 다시 열면 돼요. 똑같이 다시 채점하고, 통과하면 병합돼요.

## GitHub 계정 이름을 바꿨어요. 어떻게 하나요?

제출 폴더는 이름이 아니라 GitHub 계정(숫자 ID)에 연결돼 있어요. 이름을 바꾸면 새 이름과 폴더가 맞지 않게 되지만, 다른 사람이 예전 이름을 가져가 여러분의 작품을 수정할 수도 없어요. issue를 열어 주최자에게 연락해 주시면 폴더를 새 이름으로 바꾸는 걸 도와드려요.

## 한글과 이모지의 너비는 어떻게 세나요?

Unicode의 East Asian Width를 따라요. 한글·한자·전각 문자와 대부분의 이모지는 2칸, 다른 문자는 1칸이고, 결합 문자(예: 발음 구별 기호)는 너비가 없어요.

## 제 터미널에서는 애니메이션이 잘 나오는데, 채점할 때는 왜 화면이 한꺼번에 나오나요?

채점은 실제 터미널(pty)에서 실행되기 때문에 버퍼링 동작이 여러분의 터미널과 같아요. 흔한 원인은 프레임 사이에 <code>sleep</code>이 없거나, <code>print(..., end="")</code>를 쓰면서 줄바꿈도 flush도 하지 않아 줄바꿈이 나올 때까지 출력이 보내지지 않는 경우예요.

## 교환 짝은 어떻게 정하나요? 제 트리를 받을 수도 있나요?

<template v-if="data.schedule">마감 후 자동으로 교환돼요. 시드는 <strong>마감 전 <code>main</code> 브랜치의 마지막 커밋 sha</strong>예요. 이 시드로 채점을 통과한 참가자 모두를 섞어 원형으로 배치하고, 각자 다음 사람에게 트리를 선물하므로 <strong>자기 트리를 받는 일은 없어요</strong>. 누구나 <code>git rev-list -1 --first-parent --before={{ data.schedule.end }} main</code>로 이 시드를 확인할 수 있어요.</template><template v-else>마감 후 주최자가 미리 공지한 공개 시드로 채점을 통과한 참가자 모두를 섞어 원형으로 배치해요. 각자 다음 사람에게 트리를 선물하므로 <strong>자기 트리를 받는 일은 없어요</strong>.</template>

교환은 저장소의 Issue로 공지되고, 시드와 검증 방법이 적혀 있어요(누가 누구에게 주는지는 나오지 않아요). 누구나 같은 시드로 다시 계산해 검증할 수 있어요. 그다음 선물마다 Issue에 받는 사람을 @ 멘션한 댓글이 링크와 함께 올라오니, Watch하지 않아도 알림을 받을 수 있어요.

## 로컬에서는 되는데 왜 채점에서 실패하나요?

흔한 원인:

- 표준 라이브러리가 아닌 패키지를 썼어요
- 네트워크에 접속하거나 파일을 쓰려고 했어요
- 출력에 `\r`, `\t`, 커서 제어 코드가 들어 있어요
- 한 줄이 너무 넓어요(한글은 2칸으로 세요)
- 로컬의 언어 버전이 채점 환경과 달라요. 버전은 [언어와 여러 파일](./languages)을 참고하세요
