# よくある質問

## PR がクローズされました。どうすればいいですか？

ボットのコメントを見てください。どの項目が不合格だったか、あなたの出力、エラーメッセージが書いてあります。修正したら**新しい PR を開けば** OK です（同じブランチを使ってかまいません）。

PR を開く前に、ローカルで `pnpm judge <あなたの GitHub ID>` を実行して確認するのがおすすめです。ジャッジ環境はオンラインとまったく同じです。

## マージ後に作品を変更できますか？

できます。受付期間中に自分のフォルダを変更する PR をもう一度開いてください。同じようにジャッジされ、合格すればマージされます。

## GitHub のアカウント名を変更しました。どうすればいいですか？

投稿フォルダはアカウント名ではなく、GitHub アカウント（数値の ID）に紐づいています。名前を変えると新しい名前とフォルダが一致しなくなりますが、古い名前をほかの人が取ってあなたの作品を変更することもできません。issue を開いて主催者に連絡してください。フォルダを新しい名前に変更するお手伝いをします。

## 日本語や絵文字の幅はどう数えますか？

Unicode の East Asian Width に従います。漢字・かな・全角文字とほとんどの絵文字は 2 桁、それ以外の文字は 1 桁、結合文字（ダイアクリティカルマークなど）は幅 0 です。

## ターミナルでは正常なのに、ジャッジでは画面がまとめて出てしまうのはなぜですか？

ジャッジは本物のターミナル（pty）で実行されるので、バッファリングの挙動はあなたのターミナルと同じです。よくある原因は、フレームの間に <code>sleep</code> がない、または <code>print(..., end="")</code> で改行も flush もしていないため、改行が来るまで出力が送られないことです。

## 交換のペアはどう決まりますか？自分のツリーが当たることはありますか？

締め切り後、主催者は事前に告知した公開シードを使って、ジャッジに合格した参加者全員をシャッフルし、輪になるように並べます。それぞれが次の人にツリーを贈るので、**自分のツリーが当たることはありません**。

ペアの結果はリポジトリの Issue で発表され、誰でも同じシードで再計算して検証できます。通知を受け取るために、リポジトリの Issues を Watch しておいてください。

## ローカルでは動くのに、ジャッジで失敗するのはなぜですか？

よくある原因：

- 標準ライブラリ以外のパッケージを使っている
- ネットワークへの接続やファイルの書き込みをしようとしている
- 出力に `\r`、`\t`、カーソル制御コードが含まれている
- 1 行が広すぎる（全角文字は 2 桁で数えます）
- ローカルの言語のバージョンがジャッジ環境と違う。バージョンは[言語と複数ファイル](./languages)をご覧ください
